1 - O que são operações de “Commit”, “Push” e “Pop” efetuadas num repositório?

  • Commit: Comando interno do git para criação de um pacote (preparadas no staging com git add) com as mudanças locais realizadas em arquivos gerenciados pelo git adicionando em um pacote fechado e normalmente comentado. Funciona como um checkpoint das alterações feitas naquele momento, podendo ser desfeito ou enviado para o repositório remoto.
  • Push: Comando interno do git para realização de um envio de Commits locais para o repositório remoto.
  • Pop: Subcomando interno do git stash para reaplicar atualizações de arquivos que foram enviados para uma área temporária através do comando git stash.

2 – Quais sáo as vantagens de usar Branchs num repositório git?

Usar branches no git dá uma série de vantagens para quem desenvolve sistemas, por exemplo, é possível guardar versões diferentes de uma mesma base de códigos para que uma atualização ou mudança não afete a branch original, como uma linha do tempo alternativa que compartilha o histórico de origem, mas permite desenvolver mudanças separadamente até uma eventual integração por merge. Além disso, é possível organizar melhor as mudanças facilitando a auditoria junto dos commits.

3 – Nos Merges de conteúdos resultantes de um “Pop” podem resultar em conflitos. Em que consistem e como podem ser resolvidos esses conflitos?

Os conflitos resultantes de merges de pops são quando há alterações feitas na base atual e são aplicadas alterações que o git não consegue lidar automaticamente. Como o Git não consegue combinar automaticamente as alterações tem que haver uma ação manual que pode ter 3 formas:

  1. Manter como está;
  2. Aplicar as mudanças do merge;
  3. Combinar as duas versões, ajustando o conteúdo para resolver o conflito.

Assim se corrige um conflito de merge.

4 – “Clone” e “Fork” são formas diferentes de replicar um repositório Git. Quais as diferenças entre eles?

No git o clone é o comando básico para resgatar localmente um repositório remoto configurando, por padrão, o repositório de origem como remoto origin. Já no fork, um recurso de plataformas que utilizam o git como o GitHub, o repositório é clonado através da criação de um novo repositório sob outra conta ou organização mantendo o histórico e uma relação com o repositório original, mas com um endereço próprio. Assim é possível copiar um repositório inteiro e criar um novo produto ou contribuir com pull requests.
